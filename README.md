# Relay Workspace

업무 프로그램처럼 보이는 화면 안에서 친구들과 링크로 모여 채팅 기반 미니게임을 하는 웹앱입니다.
가입·DB·유료 API 없이 **Node 프로세스 하나**로 동작합니다.

- 첫 화면은 AI 업무 채팅 도구(“Relay”)입니다. 게임 포털, 배너, 캐릭터는 없습니다.
- 공유 세션(= 게임방)을 만들고 초대 링크를 보내면, 받은 사람은 이름만 입력해 참여합니다.
- 참여자마다 다른 인터페이스(Relay Chat / Terminal)를 써도 같은 게임을 함께 진행합니다.

> 실제 AI 모델은 호출하지 않습니다. 어시스턴트 답변은 미리 작성된 가상 업무 데이터와 오프라인 템플릿입니다.
> 화면에 나오는 업무 데이터(대화, 저장소, 로그)는 모두 허구입니다.

## 빠른 시작

```bash
npm install
npm run dev          # server :3001 + web :5173 (Vite 프록시로 /socket.io 연결)
```

브라우저에서 http://localhost:5173 을 엽니다. 다른 브라우저(또는 시크릿 창)로 초대 링크를 열면 여러 명을 흉내 낼 수 있습니다.

| 스크립트 | 설명 |
| --- | --- |
| `npm run dev` | 개발 서버 (서버 tsx watch + Vite) |
| `npm run build` | 웹 정적 빌드 → `apps/web/dist` |
| `npm start` | 프로덕션: 서버가 빌드된 웹과 WebSocket을 함께 서비스 (기본 :3001) |
| `npm test` | 서버 테스트 (게임 엔진 단위 + 실제 소켓 다중 클라이언트 통합) |
| `npm run typecheck` | 전체 TypeScript 검사 |

> WSL에서 `/mnt/c/...` 경로에 프로젝트를 두면 파일 감시가 동작하지 않아 Vite가 polling 모드로 자동 전환됩니다. 리눅스 홈 디렉터리에 두면 더 빠릅니다.

### 환경 변수 (서버)

| 변수 | 기본값 | 설명 |
| --- | --- | --- |
| `PORT` | 3001 | 서버 포트 |
| `ROOM_IDLE_MINUTES` | 30 | 접속자가 없는 세션을 정리하기까지의 시간 |
| `HOST_GRACE_SECONDS` | 20 | 호스트 연결이 끊긴 뒤 다른 참여자에게 위임하기까지 |
| `WAITING_DROP_MINUTES` | 3 | 대기/결과 단계에서 끊긴 참여자를 목록에서 빼기까지 |
| `MAX_ROOMS` | 500 | 동시 세션 수 상한 |
| `CORS_ORIGIN` | `*` | 웹을 다른 도메인에서 호스팅할 때 지정 (쉼표로 여러 개) |
| `BASE_PATH` | `/` | 하위 경로 배포 (웹 빌드와 동일하게) |

웹을 별도 정적 호스팅에 올릴 때는 빌드 시 `VITE_SERVER_URL=https://your-server` 를 지정합니다.

## 무료 운영 범위

- 상태는 **서버 메모리**에만 있습니다. 서버가 재시작되면 세션이 사라집니다(MVP 허용 범위).
- 브라우저 `localStorage` 에는 표시 이름, 인터페이스 설정, 세션 재접속 토큰만 저장합니다.
- 정적 호스팅만으로는 실시간 기능이 동작하지 않습니다. **상시 실행되는 WebSocket 서버**가 필요합니다.
  무료 플랜(슬립, 연결 시간 제한)은 호스팅마다 다르니 확인이 필요합니다. 개인 서버가 있다면 `npm run build && npm start` 한 프로세스를 리버스 프록시(Nginx 등, WebSocket 업그레이드 허용) 뒤에 두면 됩니다.

## 사용 흐름

1. 접속하면 Relay Chat 화면이 나옵니다. 왼쪽 사이드바의 **워크스페이스 → 새 공유 세션**을 누릅니다.
2. 이름과 작업 유형(Blind Review = 라이어 게임, Knowledge Check = 퀴즈)을 고르고 **세션 만들기**를 누릅니다. 나머지 설정은 기본값으로 시작할 수 있습니다.
3. 상단 **공유** 버튼이나 세션 안의 초대 링크(`/s/CODE`)를 복사해 보냅니다. 받은 사람은 이름만 입력하고 참여합니다.
4. 호스트가 **작업 시작**을 누르면 진행됩니다. 채팅은 계속 쓸 수 있습니다.
5. 결과가 나오면 **다시 실행**하거나 **유형·설정 변경**으로 다른 게임을 고릅니다.

### 인터페이스 전환

- Relay Chat: 사이드바 하단 프로필 메뉴 → *터미널 인터페이스로 전환*
- Terminal: `/theme ai` 또는 탭 오른쪽 `⌄` 메뉴
- 전환해도 세션에서 나가지 않습니다. 채팅, 타이머, 차례가 그대로 유지됩니다. 마지막 선택은 브라우저에 저장됩니다.

### 업무 보기

`Ctrl + Shift + Space`(설정에서 `Ctrl + .` 으로 변경 가능)를 누르거나 메뉴에서 *업무 보기*를 고르면 세션과 게임 영역이 숨겨지고 일반 업무 화면만 남습니다.
게임은 멈추지 않습니다. 내 차례가 오면 프로필 아바타(또는 터미널 탭)에 작은 점만 표시됩니다. 다시 누르면 서버 기준 현재 상태로 돌아옵니다. 브라우저 탭 제목에는 게임 관련 문구가 나오지 않습니다.

### Terminal 인터페이스 명령

`/help` 로 전체 목록을 볼 수 있습니다. 주요 명령은 `/new [liar|quiz]`, `/join CODE`, `/invite`, `/status`, `/start`, `/next`, `/vote N`, `/answer N`, `/say 텍스트`, `/guess 단어`, `/focus`, `/theme ai` 입니다.
일반 텍스트는 채팅으로 전송되고, 투표·응답은 `↑/↓` + `Enter`, 숫자 키, 마우스 클릭으로 고를 수 있습니다. 입력창에 `/`를 치면 명령이 자동완성됩니다.
`!git status` 처럼 `!`를 붙이면 셸 명령을 흉내 냅니다. 옆 탭은 WSL bash 를 흉내 낸 셸입니다(`ls`, `cd`, `cat`, `git status/log/diff`, `pnpm test/build/lint` 등).
**어떤 명령도 실제로 실행되지 않습니다.** 미리 정의한 명령만 문자열로 해석해 가짜 출력을 보여줍니다.

## 게임 규칙 요약 (6종)

| 업무 화면 이름 | 게임 | 인원 | 규칙 |
| --- | --- | --- | --- |
| Blind Review | 라이어 게임 | 3–10 | 1명이 몰래 라이어가 되고(카테고리만 봄) 나머지는 키워드를 봅니다. 순서대로 한 문장씩 설명(25초) → 토론(60초) → 투표(30초, 기권 가능, 변경 불가). 동률이면 동률 후보끼리 결선(20초), 결선도 동률이거나 전원 기권이면 라이어 승리입니다. 라이어가 지목되면 키워드를 1회 추측(20초, 별칭 인정)합니다. 키워드 12개 분야 331개. |
| Knowledge Check | 퀴즈 | 1–12 | 4지선다 7개 분야 125문항. 기본 7문항, 문항당 20초, 정답 공개 3초. 정답 100점 + 남은 시간 비율만큼 최대 50점. 순위는 총점 → 정답 수 → 정답 소요 시간 순, 모두 같으면 공동 순위입니다. 최근에 나온 문제는 피해서 출제합니다. |
| Access Audit | 마피아 | 5–12 | 시민·마피아만(6명 이하 1명, 9명 이하 2명, 그 이상 3명). **첫날 낮 토론부터** 시작해 토론(75초) → 투표(30초, 기권 가능, 동률이면 처형 없음) → 밤(30초) → 다음 날을 반복합니다. 마피아 전멸이면 시민 승리, 마피아 수 ≥ 시민 수면 마피아 승리, **8일째 투표까지 승부가 안 나면 무승부**입니다. 밤에 마피아가 모두 같은 사람을 고르면 2초 뒤 확정됩니다. 죽은 사람의 채팅은 관전자끼리만 보입니다. |
| Term Chain | 끝말잇기 | 2–10 | 앞 단어 끝 글자로 시작하는 단어를 냅니다(두음법칙 허용, 15초). 시간 초과면 탈락, 마지막 1명 승리. **사전이 없는 간편 모드**라 형식만 확인하고, 3명 이상이면 단어가 나온 뒤 **이의 제기 대기**(기본 5초, 이 동안 다음 차례는 시작하지 않음)를 두고, 이의가 들어오면 낸 사람을 뺀 생존자 과반이 찬성할 때 무효(낸 사람 탈락)입니다. 2명은 연습용입니다. |
| Code Match | 숫자 야구 | 1–8 | 서로 다른 숫자 3(또는 4)자리, 0으로 시작 가능. **모두 같은 번호를 동시에** 맞히고, 턴(30초)마다 한꺼번에 S/B를 공개합니다. 내가 이미 냈던 숫자는 다시 못 냅니다. 같은 턴에 맞힌 사람은 공동 승리, 최대 10턴이면 무승부입니다. |
| Requirement Discovery | 스무고개 | 2–10 | 무작위 출제자가 **정답 은행 후보 3개 중 하나**를 고릅니다(30초, 다시 뽑기 2회, 설정에서 직접 입력 허용 가능). 질문자는 **정해진 순서대로 한 명씩** 예/아니오 질문 또는 정답 도전(둘 다 1회 소모, 질문 20초·답변 15초)을 합니다. '애매함' 답은 2번까지이고 질문 횟수를 쓰지 않습니다. 출제자가 3번 답하지 않으면 중단됩니다. 오답 도전 내용은 다른 사람에게 숨깁니다. 20회 또는 **전체 8분** 안에 못 맞히면 출제자 승리입니다. |

진행 중에 들어온 사람은 관전자가 되고, 다음 라운드부터 참여합니다. 진행 중 연결이 끊겨도 10초 안에 돌아오면 그대로 이어지고(그동안은 "전원 제출" 판단에서도 기다립니다), 그보다 길면 게임별 미응답·이탈 처리됩니다. 관전·사망자 채팅은 판이 끝나도 참가자에게 공개하지 않습니다. 결과 화면은 5초 동안 유지된 뒤 다음 판을 시작할 수 있습니다. 자세한 규칙과 제시어 전체 목록은 [docs/GAME_RULES.md](docs/GAME_RULES.md)에 있습니다. 비밀 정보(라이어·마피아 역할, 키워드, 정답, 공개 전 투표·답·숫자)는 본인 또는 권한 있는 사람에게만 전송됩니다.

## 배포 (무료: 화면은 Vercel + 실시간 서버는 Render)

Vercel은 계속 연결을 유지하는 WebSocket 서버를 띄울 수 없습니다. 그래서 실시간 서버는 Render 무료 플랜에 둡니다.

1. **GitHub에 올리기:** 이 저장소를 GitHub에 push 합니다.
2. **Render (서버):** New → Blueprint → 저장소를 선택하면 `render.yaml` 대로 `relay-server` 가 생성됩니다. 웹도 함께 빌드하므로 Render 주소(`https://relay-server-xxxx.onrender.com`)만으로도 전체 앱이 동작합니다.
3. **Vercel (화면):** New Project → 같은 저장소를 고릅니다. 설정은 `vercel.json` 에 들어 있습니다. 환경 변수 `VITE_SERVER_URL` 에 Render 주소를 넣고 배포합니다. 프로젝트 이름을 `definitely-working` 처럼 정하면 `definitely-working.vercel.app` 이 됩니다.
4. **연결:** Render 환경 변수 `CORS_ORIGIN` 에 Vercel 주소를 넣고 재배포합니다.

- Render 무료 플랜은 15분 동안 접속이 없으면 잠들고, 다음 접속 때 깨어나는 데 30초~1분 걸립니다. 클라이언트는 자동으로 재연결합니다.
- 서버가 잠들거나 재시작하면 진행 중이던 세션은 사라집니다(메모리 저장).
- 하위 경로에 배포하려면 웹 빌드와 서버 실행에 같은 `BASE_PATH=/경로/` 를 지정합니다.

## 구조

```
packages/shared    이벤트 계약, 타입, Zod 스키마, 게임 메타데이터
apps/server        Node + Socket.IO (단일 프로세스, 메모리 상태)
  src/games/       테마를 전혀 모르는 게임 엔진 6종 — GameEngine 인터페이스, registry.ts 에 등록
  src/rooms/       Room(참여자/호스트/채팅/단계), RoomManager(정리·위임)
  src/socket/      요청 검증(Zod), 레이트 리밋, 참여자별 개인화 스냅샷 전송
apps/web           React + Vite + Zustand
  src/game-ui/     테마 독립 모델: 스냅샷 → "지금 내가 할 일(task)" 변환
  src/themes/ai-chat   Relay Chat 렌더러
  src/themes/terminal  Windows Terminal + Relay CLI + 가상 bash 렌더러
```

- 게임 엔진은 상태만 관리하고, 테마는 `game-ui` 모델을 각자 방식으로 그립니다. 같은 이벤트가 Chat에서는 작업 블록과 로그로, Terminal에서는 CLI 출력과 선택 프롬프트로 보입니다.
- 서버는 상태가 바뀔 때마다 **참여자별로 걸러낸 스냅샷**을 보냅니다. 라이어의 정체, 키워드, 다른 사람의 투표나 답은 공개 시점 전까지 권한 없는 클라이언트에 전송되지 않습니다. 통합 테스트에서 라이어가 받은 실제 소켓 데이터에 키워드가 없는지도 확인합니다.
- 타이머, 차례, 투표, 정답 판정은 모두 서버에서 처리합니다. 클라이언트는 서버 시계와의 차이만 보정해 남은 시간을 표시합니다.

### 소켓 이벤트

클라이언트 → 서버 요청은 모두 ack 콜백으로 `{ ok: true, data } | { ok: false, error: { code, message } }` 를 받습니다:
`room:create`, `room:join`, `session:resume`, `room:peek`, `room:leave`, `room:configure`, `chat:send`, `game:start`, `game:action`, `game:stop`.
서버 → 클라이언트 알림은 `room:state`(개인화 스냅샷), `chat:message`, `room:closed` 입니다.

### 보안·안정성

- 모든 요청은 Zod로 검증하고 길이를 제한합니다. 채팅, 동작, 세션 생성·참여 요청에는 소켓별 레이트 리밋이 걸려 있습니다.
- 채팅은 React 텍스트로만 렌더링합니다. 마크다운 렌더러도 HTML을 해석하지 않으므로 XSS 위험이 없습니다.
- 초대 코드는 혼동되는 문자를 뺀 6자리(약 8.9억 조합)이고, 세션당 최대 16명(참여자 + 관전자)입니다.
- 재접속은 브라우저에 저장한 임시 토큰(192비트)으로 본인을 확인합니다. 위조 토큰은 거부됩니다.
- 빈 세션, 타이머, 끊긴 참여자는 주기적으로 정리합니다. 호스트가 나가거나 연결이 끊기면 다른 참여자에게 위임합니다.
